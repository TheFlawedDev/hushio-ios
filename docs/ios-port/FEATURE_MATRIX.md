# Initial feature matrix — source-backed, iOS pending

Baseline: **`2122110f9b41436723f368d3e1fb4d8a2a4276c2`**. Companion references: `SOURCE_ATLAS.md` (architecture, test attempt, discrepancy IDs D01–D18) and `BEHAVIOR_CONTRACTS.md` (P playback / S services contracts).

## Reading the matrix

- **Every row is `P` = pending / unverified on iOS, not implemented.** No iOS implementation, device evidence or credential check was performed by this role. “Shared” means existing code to retain, not that it runs on iPhone today.
- Active, optional, dormant and OS-specific source are distinguished in the text. OS-specific rows remain pending classification; “candidate inapplicable” is not an approved omission. The lead must record a reason/evidence before changing status.
- Owners are roles: **Platform** = Senior Tauri and Rust Platform Engineer; **Media** = Senior iOS Media Engineer; **Services** = Senior iOS Services Engineer; **React** = Senior React Port Engineer; **Design** = Principal App Designer; **QA** = QA and Behavioral Parity Engineer; **Release** = Build and Release Engineer; **Lead** = Senior Lead Engineer. The first listed role is accountable; QA participates in every acceptance scenario.
- Source path shorthand: `V/` = `src/views/`; `C/` = `src/components/`; `L/` = `src/lib/`; `Z/` = `src/stores/`; `R/` = `src-tauri/src/`; `K/` and `KT/` as defined in the atlas. Tests sharing a source basename are written `same-name.test.ts[x]` where unambiguous. These are existing tests to run, **not pass claims**.
- Each acceptance scenario includes fresh/loading/empty/error states where relevant and comparison against the baseline. Device/background scenarios require a physical iPhone; simulator-only proof is insufficient.
